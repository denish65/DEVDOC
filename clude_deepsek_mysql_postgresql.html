MySQL‑specific concepts

InnoDB & MySQL internals

  • Storage engines: InnoDB (default, transactional) vs MyISAM (legacy)
  • InnoDB clustered index – primary key is the table
  • AUTO_INCREMENT gaps & behaviour
  • Replication formats: statement‑based, row‑based, mixed
  • Query cache (deprecated/removed in MySQL 8) – why it was removed
  • SHOW commands: PROCESSLIST, ENGINE INNODB STATUS
  • Character sets & collations (utf8 vs utf8mb4)
  • JSON column support (MySQL 5.7+)

PostgreSQL‑specific concepts

PostgreSQL superpowers

  • MVCC implementation – dead tuples, VACUUM / autovacuum
  • VACUUM vs VACUUM FULL vs autovacuum tuning
  • Sequences (explicit, flexible) vs AUTO_INCREMENT
  • Advanced types: JSONB, arrays, hstore, ranges, ENUM, native UUID
  • Extensions: pg_stat_statements, PostGIS, pg_trgm, uuid‑ossp
  • Row‑Level Security (RLS) – no direct MySQL equivalent
  • Table inheritance & declarative partitioning
  • Full‑text search (native, more powerful)
  • Foreign Data Wrappers (query external sources as local tables)
  • Custom functions/procedures (PL/pgSQL, Python, etc.)
  • Triggers – more powerful & flexible
  • CTEs are “true” – recursive & flexible
  • EXPLAIN (ANALYZE, BUFFERS) – richer plan output
Anchor concept: MySQL InnoDB clusters the table by primary key (data stored in PK order), while PostgreSQL stores rows in heap order regardless of PK. This single difference explains why indexing and performance strategies diverge so much between the two engines.

Advanced — MySQL vs PostgreSQL deep dive

Do not read this until Phases 1–10 feel comfortable. This is where the real production gotchas live.

1 · Side‑by‑side behavioural differences (classic production bugs)

Concept MySQL PostgreSQL
Default isolation level REPEATABLE READ READ COMMITTED
FULL OUTER JOIN ❌ Not supported (emulate with UNION) ✅ Native support
Boolean type TINYINT(1), TRUE/FALSE = 1/0 Real boolean type
Identifier case sensitivity Table names case‑sensitive on Linux, insensitive on Win/macOS Unquoted identifiers folded to lowercase
String case sensitivity in WHERE Depends on collation (usually insensitive) Case‑sensitive by default (use ILIKE / citext)
LIMIT / OFFSET syntax LIMIT n OFFSET m LIMIT n OFFSET m or FETCH FIRST n ROWS
Auto‑increment column AUTO_INCREMENT SERIAL / GENERATED ... AS IDENTITY
Foreign key → index ✅ Auto‑creates index on FK column ❌ Does not auto‑create (must add manually)
Timestamp with timezone TIMESTAMP (stores UTC), DATETIME (no TZ) TIMESTAMPTZ (recommended), TIMESTAMP (no TZ)
String concatenation CONCAT() or || (if PIPES_AS_CONCAT) || or CONCAT()
GROUP BY strictness Allows non‑aggregated columns (unless ONLY_FULL_GROUP_BY) Strict — every non‑aggregated column must be in GROUP BY
NULL ordering in indexes NULLs sort first by default NULLs sort last by default (ASC)
Regex support REGEXP (POSIX-ish) ~, ~* (POSIX regex) + SIMILAR TO
Upsert syntax INSERT ... ON DUPLICATE KEY UPDATE INSERT ... ON CONFLICT ... DO UPDATE
Returning modified rows ❌ No direct RETURNING (need workarounds) ✅ RETURNING * on INSERT/UPDATE/DELETE
JSON storage JSON (binary, validated) JSON (text) vs JSONB (binary, indexable) — prefer JSONB

2 · Production operations (Phase 11 — beyond the core map)

Connection management

  • max_connections tuning
  • MySQL: ProxySQL, MySQL Router
  • Postgres: PgBouncer, PgPool‑II
  • Transaction vs session pooling modes

Monitoring & observability

  • MySQL: performance_schema, sys schema, SHOW ENGINE INNODB STATUS
  • Postgres: pg_stat_activity, pg_stat_statements, pg_stat_user_tables
  • Prometheus + mysqld_exporter / postgres_exporter
  • Grafana dashboards

Logging

  • Error logs, slow query log
  • MySQL: slow_query_log, long_query_time
  • Postgres: log_min_duration_statement, log_lock_waits
  • Log rotation & retention

Configuration tuning

  • MySQL: innodb_buffer_pool_size, innodb_log_file_size, innodb_flush_log_at_trx_commit
  • Postgres: shared_buffers, work_mem, effective_cache_size, maintenance_work_mem
  • WAL / binlog size tuning

Backup & restore tools

  • MySQL: mysqldump, mysqlpump, mydumper, XtraBackup
  • Postgres: pg_dump, pg_dumpall, pg_restore, pg_basebackup
  • Point‑in‑time recovery (PITR) with WAL / binlog archiving

Replication & failover

  • MySQL: binlog position / GTID, group replication
  • Postgres: streaming replication, logical replication slots
  • Failover: Orchestrator (MySQL), Patroni / repmgr (Postgres)
  • Replication lag monitoring

Timeouts & safety

  • Postgres: statement_timeout, idle_in_transaction_session_timeout, lock_timeout
  • MySQL: max_execution_time, wait_timeout
  • Killing runaway queries safely

Managed cloud services

  • MySQL: Amazon RDS, Aurora, Cloud SQL, PlanetScale
  • Postgres: RDS, Aurora, Cloud SQL, Supabase, Neon, Timescale
  • Know what you give up vs self‑hosted

Upgrade paths

  • MySQL: in‑place upgrade, logical dump/reload
  • Postgres: pg_upgrade (in‑place), pg_dump/pg_restore (logical)
  • Major version breaking changes to watch

ORM integration (Laravel / Eloquent)

  • How Eloquent generates different SQL per driver
  • JSON column queries: MySQL vs Postgres syntax
  • Upsert, RETURNING, and lock behaviours
  • Migrations that work on both engines
